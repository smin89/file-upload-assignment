# AI 활용 및 개발 기록

> 파일 업로드 과제를 진행하면서 AI를 어떤 단계에서 활용했고, AI의 제안을 어떻게 검토·수정·검증했는지 정리했습니다. 
> 대화 전문을 단순 복사하기보다 **질문의 목적 → 주요 프롬프트 → AI 제안 → 실제 판단/반영**이 드러나도록 시간 순으로 재구성했습니다.

## 1. AI 활용 방식

AI는 코드를 대신 작성하는 도구라기보다 요구사항 분석, 설계 선택지 비교, 예외 케이스 탐색, DB/API 초안, Spring Boot·React 구현 검토, 오류 분석, 테스트 보완, Git/배포 점검, 제출 문서 정리에 활용했습니다. 
제안은 바로 적용하지 않고 요구사항과 실제 소스에 맞는지 확인한 뒤 **채택 / 수정 / 제외**했습니다.

# 2. 프롬프트 / 입력 기록

## 2026-09-29 --- 과제 분석 및 구현 범위 결정

### 목적

구현 전에 필수 기능과 고려 항목을 분리하고 불필요한 기능 개발을 줄이기
위해 과제 분석을 요청했습니다.

### 주요 프롬프트

> "과제를 분석하고, 단계별로 어떻게 진행하면 좋을지 정리해줘."

> "요구사항 정리해서 리스트로 보여주고 과제에는 없지만 추가하면 좋을만한 사항 있으면 같이 넣어줘."

### AI 제안

서버 최종 검증, 입력 정규화, 다중 확장자, dotfile/무확장 파일, 0 byte, UUID 저장, MIME/Magic Number 검사 여부 등을 먼저 정책으로 정하도록 제안했습니다.

### 실제 판단 / 반영

확장자 정책 관리와 실제 업로드 검증을 핵심 범위로 정했습니다. 
파일 목록·다운로드·삭제는 필수 요구가 아니어서 제외했고, 서버 검증·다중 확장자 검사·UUID 저장·0 byte 거부는 반영했습니다. 
Magic Number와 악성코드 검사는 별도 보안 계층으로 판단하여 향후 개선사항으로 남겼습니다.

# 4. 판단 근거 회고

## 그대로 또는 방향을 채택한 것

서버 최종 검증, 확장자 정규화, 대소문자 통일, 다중 확장자 검사, UUID 저장명, DB UNIQUE 제약, 전체 파일 선검증, DB 실패 시 파일 보상 삭제, 설정 변경 후 서버 재조회, 업로드 자동 재시도 제외는 요구사항과 구조에 적합하다고 판단해 방향을 채택했습니다.

## 고쳐 쓴 것

-   **DB 설계:** 불필요한 사용자, AI 분석 결과, 별도 검증 결과 구조 제거
-   **dotfile:** 일반적인 전면 차단 대신 현재 정책상 `.env` 허용, `.env.exe`는 검사 차단
-   **Magic Number/MIME:** 필요성은 인정하되 현재 구현처럼 표현하지 않고 향후 개선으로 분리

## 버린 것 / 구현하지 않은 것

원본 요구사항에 없는 파일 목록·다운로드·삭제, AI 분석 결과 저장, 현재 규모에서 필요성이 검증되지 않은 캐시, 인증 없는 상태의 변경자 Audit, Magic Number·악성코드 검사, S3 연동은 현재 범위에서 제외했습니다.

# 5. 최종 회고

이번 과제에서 AI가 가장 도움이 된 부분은 **놓칠 수 있는 예외 상황을 드러내고 구현 선택지를 비교하는 과정**이었습니다.
실제 작업은 다음 흐름으로 진행했습니다.
`요구사항 확인 → 구현 범위 결정 → AI에 대안 질문 → 현재 프로젝트에 맞는 방법 선택 → 구현 → 테스트 → 실제 결과 확인 → 부족한 부분 재질문 → 문서화`
최종적으로 AI는 설계·구현·검증·문서화의 보조 도구로 활용했고, 실제 반영 여부는 요구사항, 코드, 테스트 및 배포 결과를 기준으로 직접 판단했습니다.
